SAT301 · Final-year thesis · Python / TensorFlow

Learning when to offload computation

A multi-head neural approach to choosing which mobile tasks should run locally and which should move to an edge server.

01 Goal02 My role03 Method04 Results05 Demo06 Resources

01 · Problem & goal

Problem & goal

Exhaustive offloading search grows with the number of mobile users. A useful predictor must balance decision quality, latency and the resulting computation cost.

02 · My contribution

My contribution

My thesis evaluates a shared-backbone multi-head model against an MTL-FNN baseline and examines the gap between oracle-assisted and label-free head selection.

03 · Implementation approach

Implementation approach

Six features per user describe input size, CPU work, local CPU frequency, channel gain and latency/energy preferences. Shared layers feed specialized prediction heads. Experiments compare decision-vector accuracy, squared error, offloading cost and prediction time. Oracle-assisted selection is kept distinct from label-free selection.

04 · Results & reflection

Results & reflection

Five-head accuracy exceeds the baseline in the supplied log, but higher accuracy does not always reduce cost. Oracle selection remains an upper bound rather than a deployable decision rule.

Evidence & limits

Oracle-assisted selection uses ground-truth labels, so the plotted accuracy is a diagnostic upper bound. At five and seven users, higher accuracy still leads to higher offloading cost. This makes deployable selection and cost-aware evaluation the central research questions.
