Learning when to offload computation

A multi-head neural approach to choosing which mobile tasks should run locally and which should move to an edge server.

01 · The problem

Exhaustive offloading search grows with the number of mobile users. A useful predictor must balance decision quality, latency and the resulting computation cost.

02 · My contribution

My thesis evaluates a shared-backbone multi-head model against an MTL-FNN baseline and examines the gap between oracle-assisted and label-free head selection.

03 · The approach

Train a shared representation and specialized heads on synthetic MEC data; evaluate complete decision vectors, squared error, offloading cost and prediction time across 2–8 users.

04 · The finding

Five-head accuracy exceeds the baseline in the supplied log, but higher accuracy does not always reduce cost. Oracle selection remains an upper bound rather than a deployable decision rule.

How the model makes a decision

Each user contributes six features: input data size, CPU cycles, local CPU frequency, channel gain, and latency and energy weights. Shared dense layers feed several prediction heads, each producing one offload decision per user.

The thesis compares selection strategies because the best head is not known at deployment. Choosing it using test labels can diagnose the model’s potential, but cannot be used as a real-time policy.

The five-head forward-pass timings are 0.0177–0.0211 ms per sample in this log. They exclude the full deployed pipeline and do not establish edge-device latency. The README’s “550×” compares a timing to a target, not a measured baseline speedup.

Implementation work described in the project notes

The supplied README describes manual per-head loss accumulation, global gradient clipping, dynamic-head compatibility work, dataset delimiter detection and warmed-up XLA inference. These describe implementation changes; the actual Python files are still needed to verify them.

What is established, and what remains open

The thesis and supplied log support the research results above. The README attributes the implementation to the open-source MTFNN-CO baseline, associated with the IEEE TMC 2020 and GlobeCom 2023 work; this project builds on that prior work.

The supplied dependency export pins TensorFlow/Keras 2.8, while the README describes Keras 3 compatibility. A matching source revision and environment are needed before calling this package reproducible. No edge-device deployment or new training run is claimed.
