01 · Problem & goal

Problem & goal

Connect activity records and calendar plans so a daily diary can reflect what the user actually did.

02 · My contribution

My contribution

I designed the overall interface in Figma, implemented and refined the calendar module, integrated it with teammates’ components, and created workflow diagrams and the report sections explaining calendar and integration decisions.

03 · Implementation approach

Implementation approach

Calendar tasks connect with teammates’ activity records and diary-generation modules. My work covers the Figma interface, calendar implementation, module integration and workflow documentation. Android permissions and background-service behavior are integration constraints described in the report.

How the calendar fits the whole application

  1. Plan: create and manage calendar events and tasks through a consistent interface.
  2. Connect: integrate calendar data with teammates’ activity-tracking and stored behavior records.
  3. Reflect: make planned events available to the team’s diary-generation workflow, so summaries can relate activity to the day’s schedule.

The report describes a calendar data model with persistence and reminder integration. My contribution was the interface, calendar feature and cross-module integration; sensor recognition and AI generation were collaborative components.

Two data streams, one daily story

  1. Phone sensors → behavior records
  2. Calendar plans → schedule records
  3. Stored activity + planned events → daily reflection

My calendar and interface work

A schedule entry stores an ID, title, target/description, date and completion flag. Calendar views make these records usable, while integration connects them with the application’s other components.

The wider team system

A foreground perception service coordinates sensing, location and state changes. A local behavior database stores records for history and diary generation. These components were developed collaboratively.

04 · Results & reflection

Results & reflection

The application connects calendar plans with tracked activity and diary generation. My contribution makes the calendar usable within that larger workflow, rather than leaving it as an isolated feature.

Why the interface decisions matter

  • Dashboard: grouped entry points and explanatory text help users understand available functions.
  • History: chronological activity records make the day reviewable and editable.
  • Lightweight categories: simple tags avoid an unnecessarily complex editing flow.
  • Calendar context: planned events give the diary more context than step totals alone.

Source: DailySense report §3.2 interaction design.

Integration lesson

Calendar plans, activity history and daily reflections work best as one user journey. Permission handling and background-service behavior are part of making that journey reliable.
